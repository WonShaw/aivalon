# Aivalon · AI 阿瓦隆

一群 AI（默认 Claude Opus 5.5）玩阿瓦隆，支持 8 人局和 10 人局。人可以在网页上观战，也可以入座和 AI 一起玩。

## 运行

需要 Node 20+，并且本机已登录 Claude Code（AI 玩家通过 Claude Agent SDK 调用，使用 Claude Code 的登录凭证）。

```bash
npm install
npm run dev
```

打开 http://localhost:5180 。后端 API 在 8787 端口，可以用 `AIVALON_API_PORT` 修改。

### 局域网联机

前端开发服务器监听所有网卡，`npm run dev` 启动后终端里 `Network:` 那一行就是局域网地址（例如 `http://192.168.1.5:5180`）。

- 开局的人请用这个局域网地址打开大厅再创建对局，这样生成的玩家专属链接别人才能打开。用 localhost 打开时，链接里也是 localhost，需要手动换成本机 IP。
- 其他人只需要访问 5180 端口，前端会把 `/api` 转发到本机的后端。
- 如果打不开，检查本机防火墙是否允许 Node 接受 5180 端口的入站连接（Windows 首次启动时会弹窗询问，要勾选"专用网络"）。
- 也可以先 `npm run build` 再 `npm start`，这时后端在 8787 端口同时提供页面和 API，局域网里访问 `http://<本机 IP>:8787` 即可。

注意：同一局域网里的任何人都能打开大厅、开新局（消耗你的 Claude 额度）和删除已结束的对局。只在信任的网络里这样用。

可选环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `AIVALON_THINKING_DISPLAY` | `summarized` | 设为 `omitted` 后不再获取思考摘要 |

其他命令：

- `npm run simulate`：用脚本玩家把 8 人和 10 人的每种预设都跑一遍完整局，检查状态机、身份分配和信息可见性，不调用模型
- `npm run check-isolation`：调用一次模型，让 AI 报告它的上下文里有哪些工具和附加信息
- `npm run typecheck` / `npm run build`

## 规则

支持 8 人局（5 名正义方、3 名邪恶方）和 10 人局（6 名正义方、4 名邪恶方），两种人数的任务人数都是 3/4/4/5/5。

开局时可以选择身份配置：梅林和刺客必选；派西维尔可选，不选就换成一名忠臣；邪恶方除刺客外的位置可以从莫甘娜、莫德雷德、奥伯伦里选（8 人局最多 2 个，10 人局最多 3 个），空位由莫德雷德的爪牙补上。预设：

| 人数 | 预设 | 正义方 | 邪恶方 |
|---|---|---|---|
| 8 | 标准 | 梅林、派西维尔、忠臣×3 | 刺客、莫甘娜、莫德雷德 |
| 8 | 奥伯伦 | 梅林、派西维尔、忠臣×3 | 刺客、莫甘娜、奥伯伦 |
| 8 | 入门 | 梅林、忠臣×4 | 刺客、爪牙×2 |
| 10 | 标准 | 梅林、派西维尔、忠臣×4 | 刺客、莫甘娜、莫德雷德、奥伯伦 |
| 10 | 不含奥伯伦 | 梅林、派西维尔、忠臣×4 | 刺客、莫甘娜、莫德雷德、爪牙 |
| 10 | 入门 | 梅林、忠臣×5 | 刺客、爪牙×3 |

开局时还可以选择 AI 玩家使用的模型（Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 5.1，默认 Opus 5.5）和推理强度（低 / 中 / 高 / 很高 / 最高，默认中）。所有 AI 用同一配置，记在对局记录里，开局后不能更改，赛后交流也沿用。

人类玩家可以选择身份：随机（默认）、正义方随机、邪恶方随机，或者本局配置里的某个具体身份。选择只有本人知道。

每个玩家都有一个像素风头像（亚瑟王传说风格的人物，和真实身份无关）：每个 AI 名字固定一个，人类玩家在大厅里点名字旁边的头像可以换成任意一个。

第 4 个任务需要 2 张失败票才算失败；组队投票需要超过半数赞成；同一任务的组队连续 5 次被否决时邪恶方获胜（每个任务分别计算，不跨任务累计）。

每次组队的流程：队长发言并提名 → 其余人按座位顺序各发言一次 → 队长确认或修改提名 → 全员同时投票。正义方完成 3 个任务后进入刺杀阶段：邪恶方公开身份并讨论，由刺客决定刺杀目标。

**提前刺杀**：刺客（人类或 AI 都可以）在组队和任务阶段轮到自己行动时（提名、发言、最终提名、投票、出任务牌），可以不做这个动作，改为发起提前刺杀（不选目标，发言可选，作为刺杀宣言公开）。当前的组队和任务作废，直接进入和 3 个任务成功后一样的刺杀阶段：邪恶方全部亮明身份并依次讨论，最后由刺客选择刺杀目标，刺中梅林邪恶方获胜，刺错正义方获胜。正在思考的其他 AI 不会被打断，等它们做完后结果作废，再进入刺杀阶段。AI 刺客通过提交 `assassinate` 动作发起，不需要额外的输出字段；组队和任务阶段每次轮到 AI 刺客行动时，裁判的指令末尾都会提醒它可以改为提前刺杀，并说明提交后会直接进入刺杀阶段，之后再选目标。

**赛后交流**：对局正常结束后，可以点"赛后聊聊"开启赛后交流，所有人按座位顺序各发言一次（人类可以跳过）。一轮结束后可以点"再聊一轮"继续，轮数不限；AI 能看到前面几轮所有人的发言。有人类玩家的对局，玩家还可以点"单独聊聊"，在圆桌上选一名 AI 对他说话，这名 AI 会回复；单独对话也是公开的，所有人都能看到，之后其他 AI 发言时（轮流发言或别人找它单独对话）也能看到。轮流发言或单独对话进行中时，要等它结束才能开始下一次。

**语音朗读**：对局页面顶栏可以打开"语音朗读"，用浏览器自带的 Web Speech API 读出发言和流程播报（组队、投票、任务结果、刺杀、胜负），免费，用系统自带的声音时离线可用。每个座位分配一个固定的声音，优先用高音质、优化音质的中文声音，不用机器味很重的 Eloquence 声音（macOS 可以在 系统设置 → 辅助功能 → 朗读内容 → 系统声音 → 管理声音 里下载更好的中文声音）。开启后服务端照常进行，前端把新事件放进缓冲队列，读完一条再显示下一条，读到谁的发言，圆桌上谁的座位就显示发言动画；落后时对局状态、谁正在行动、轮到你的操作都等追上后再显示，可以点"跳到最新"跳过积压。打开页面时，30 秒以内刚发生的内容（例如新开局时的"游戏开始"和第一次组队）照常朗读，更早的直接显示、不读。

## 设计要点

**信息隔离**
- 服务端是唯一知道全部信息的地方。每条事件都标注了可见范围：公开、仅某些座位，或仅观众。
- 每个 AI 收到的内容，是它能看到的事件渲染成的文本，以新的 user 消息追加到它自己的会话里。
- 人类玩家的推送同样在服务端过滤，前端拿不到不该看的数据。
- 全 AI 对局的观众能看到 AI 的调用统计，也可以开上帝视角，看所有人的身份、任务牌和 AI 的思考摘要。有人类参与的对局只能用玩家的专属链接进入；对局正常结束后，玩家的页面和观众一样能看到这些，赛后交流轮到自己时照常发言。这些都不会进入任何 AI 的上下文。
- **调试模式**：对局页面勾选"调试"后，本局所有人（包括有人类参与的对局里的每位玩家）都能看到全部身份和 AI 的思考摘要；有人类的对局开启前会确认。调试模式下可以勾选"暂停"：已经开始的 AI 调用照常完成，之后不再发起新的调用，取消勾选后按正常流程继续（人类玩家的操作不受影响）。也可以点"裁判提问"，以裁判身份问某个 AI 问题：它在从自己游戏会话 fork 出来的临时会话里回答，记得游戏里的一切，但回答不进入游戏、其他 AI 看不到；接着问会延续这段调试对话，它在游戏里又行动过的话下一次会重新 fork。问答只在调试模式下显示在时间线上，fork 出的会话在删除对局时一起删掉。

**AI 进程的限制**（见 `server/ai/player.ts`）
- 关闭全部内置工具（`tools: []`），不加载 `~/.claude` 和项目里的设置或 CLAUDE.md（`settingSources: []`），也不挂 MCP、插件和 skills。
- 权限模式是 `dontAsk`，并且 `canUseTool` 一律拒绝。
- 工作目录是一个空的临时目录。
- 打开 `verbatimPrompts`：发言里的 `@路径` 不会被展开成文件内容，也不会触发斜杠命令。发言里的 `<` `>` `@` 和"【裁判】"会被转义，防止伪造裁判消息或其他玩家的发言。
- 启动 AI 进程前，会去掉宿主环境（比如在 Claude 桌面 App 里运行时）带进来的会注入额外上下文的环境变量。

**会话与缓存**
- 每个 AI 一个 Agent SDK 会话，每次行动都 resume 同一个 session id。session id 记录在 `data/games/<id>/game.json`。
- 在大厅删除一局时，会同时删除 `data/games/<id>/` 和这局所有 AI 的会话记录（Agent SDK 存在 `~/.claude/projects/` 下）。进行中的对局不能删除。
- 系统提示词对所有 AI、所有对局都一样，写的是包含所有可能身份的通用规则。本局配置、座位和身份都放在第一条 user 消息里。
- 所有动作共用一个结构化输出 schema。Agent SDK 用一个工具实现结构化输出，每次换 schema 会让整段缓存失效。

**思考过程**：只使用 API 官方提供的思考摘要（`display: "summarized"`），不要求模型在输出里写出推理过程。模型会自己决定每一步要不要思考，简单的回合（例如第一轮发言）可能不思考，所以不会每一步都有摘要。

**防止从时间推断信息**：有人类参与时，所有队员都要出任务牌，任务结算至少等 8 到 12 秒，避免从结果出来的快慢推断队伍里有没有邪恶方。出牌状态不会推送给其他玩家。

## 已知限制

- Claude Code 会把登录账号的邮箱作为用户上下文注入每个会话。它不影响游戏公平，但 AI 能看到。要去掉，需要用 `claude setup-token` 生成独立的 token，再给 AI 进程设置单独的 `CLAUDE_CONFIG_DIR`，目前没有实现。
- 服务进程重启后，进行中的对局会被标记为中止，不支持续局。
- 同一时间只能进行一局。
